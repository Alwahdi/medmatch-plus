# سد فجوات وثيقة المتطلبات — Phase 104

مطابقة وثيقة Syndeocare مع المبني حالياً. الموجود مسبقاً: التسجيل والأدوار، الملفات والمستندات، الوظائف والمناوبات، التقديم والحجز، المراسلة، الدعوات، التقييمات الثنائية (5 نجوم + تعليق)، التوثيق اليدوي عبر الأدمن، الفلاتر والبحث. المدفوعات تبقى يدوية خارج المنصة (قرارك: بدون دفع حالياً) — لن نضيف أي بوابة دفع.

## ما سيُبنى (4 حزم)

### 1) الموقع والنطاق الجغرافي
- إضافة إحداثيات اختيارية (خط عرض/طول) لملف الكادر والمنشأة: زر «استخدم موقعي الحالي» عبر متصفح المستخدم + إدخال يدوي.
- نطاق بحث بالمسافة (كم): المنشأة تختار نصف قطر في بحث المرشحين، والكادر يختار نطاق القبول في ملفه.
- المسافة تُحسب وتُعرض في نتائج البحث («على بُعد 12 كم») وترتيب اختياري بالأقرب.
- الخصوصية محفوظة: الإحداثيات الدقيقة لا تظهر للطرف الآخر — تظهر المسافة فقط.

### 2) التوفر والأجور والأرباح
- الكادر: أيام/أوقات التوفر الأسبوعية + سعر مرغوب بالساعة/اليوم (YER افتراضياً).
- صفحة «نشاطي» للكادر: المناوبات المكتملة وإجمالي المستحقات المحسوبة من أسعار المناوبات (عرض معلوماتي فقط — الدفع يدوي خارج المنصة).
- المنشأة: ملخص توظيفات مكتملة وتكاليفها التقديرية.
- فلتر «متاح هذا الأسبوع» في بحث المرشحين.

### 3) إعادة التوظيف وPush
- زر «إعادة توظيف / تكرار مناوبة» في سجل المنشأة: ينشئ مناوبة جديدة منسوخة من سابقة مكتملة، ويرسل دعوة لنفس الكادر عبر RPC الدعوات الموثوق الحالي (بدون أي اختصار إدراج مباشر).
- إشعارات Push للمتصفح (Web Push): صفحة إعدادات تفعيل لكل جهاز، إرسال عند الأحداث المهمة (دعوة، قبول/رفض، مقابلة، نتيجة توثيق). بدون أي نص محادثة خاص في الإشعار — عنوان عام فقط (يلتزم بقاعدة الخصوصية من Phase 101).

### 4) تنبيهات انتهاء المستندات
- إشعار استباقي داخل المنصة قبل انتهاء المستند المطلوب بـ30 يوماً و14 يوماً ويوم الانتهاء — لكل من الكادر والمنشأة (idempotent، يُرسَل مرة واحدة لكل عتبة).
- يعمل ضمن مهمة التحديث اليومية الموجودة (refresh-verification) — بدون endpoint جديد.
- شارة «ينتهي قريباً» موجودة حالياً في الواجهة وتبقى كما هي.

## ما لن يتغير
- لا بوابات دفع ولا Stripe ولا Escrow — الدفع يدوي خارج المنصة كما قررت.
- لا بريد/WhatsApp حتى تجهيز الاعتمادات.
- لا تغيير على سياسات الخصوصية الحالية (إخفاء اسم المنشأة، صلاحيات الزوار، إلزام MFA للأدمن).
- لا بيانات تجريبية في واجهة الإنتاج؛ بيانات الاختبار تُحذف بعد الفحص.

## تفاصيل تقنية
- Migration واحدة: أعمدة `lat`/`lng` (numeric, nullable) و`availability` (jsonb) و`search_radius_km` على `healthcare_professionals`؛ أعمدة `lat`/`lng` على `facilities`؛ جدول `push_subscriptions` (user_id, endpoint, keys) بسياسات مالك-فقط + GRANTs؛ جدول `expiry_alert_log` لمنع تكرار التنبيهات؛ دالة حساب مسافة (Haversine) SECURITY DEFINER بـsearch_path مثبّت تعيد المسافة فقط دون الإحداثيات؛ توسيع `refresh_verification_expiry` لإرسال تنبيهات الانتهاء؛ دالة `rehire_shift` ذرّية تنشئ مناوبة جديدة + دعوة في معاملة واحدة.
- RLS: الإحداثيات يقرأها المالك فقط؛ المسافة تُحسب خادمياً عبر RPC البحث الموجود (`search_candidates_idempotent` ونظيره العام) وتُعاد كرقم فقط.
- Push: Web Push عبر VAPID (مفاتيح تُولّد وتُخزن كأسرار)، service worker صغير، الإرسال من مهمة خادمية بعد إنشاء الإشعار الداخلي.
- الواجهة: حقول الموقع/التوفر/الأجور في نماذج الملف (كادر + منشأة)، بطاقة الأرباح في نشاط الكادر، زر إعادة التوظيف في سجل المنشأة، مفتاح تفعيل Push في الإعدادات — كلها عربي/إنجليزي RTL/LTR وبنفس نظام التصميم الحالي.

## الاختبار
- فحص SQL: خصوصية الإحداثيات (الزائر والطرف الآخر لا يقرآنها)، idempotency للتنبيهات، ذرّية إعادة التوظيف.
- فحص بناء + typecheck.
- تجربة متصفح على 390 و1280: تعيين موقع، بحث بالنطاق، إعادة توظيف، تفعيل Push — ثم حذف كل بيانات الاختبار.
