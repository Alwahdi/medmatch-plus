# خطة إعادة بناء تجربة SyndeoCare Mobile بالكامل

## الهدف
إعادة بناء تجربة تطبيق الجوال من أول فتحه حتى إتمام التوظيف أو المناوبة، بنظام واضح وسريع ومنظم مستلهم من انضباط Binance في ترتيب المعلومات والإجراءات، مع الحفاظ على هوية SyndeoCare الطبية الهادئة، العربية أولاً، والخصوصية الحالية.

لن ننسخ ألوان Binance أو طابع التداول أو كثافته. سننقل فقط: وضوح الأولويات، قلة الإجراءات الأساسية، الحالات الدقيقة، وسرعة الوصول.

## المبادئ الحاكمة
- شاشة واحدة = هدف أساسي واحد.
- أول معلومة يراها المستخدم هي الأهم لحالته الآن.
- لكل شاشة إجراء أساسي واحد، والبقية ثانوية أو داخل قائمة سياقية.
- تجربة المختص والمنشأة منفصلتان بعد اختيار نوع الحساب.
- لا شاشة مسدودة بعبارة «استخدم الموقع»؛ كل رحلة أساسية تعمل داخل التطبيق.
- لا بيانات وهمية، ولا وعود توثيق غير حقيقية، ولا كشف لهوية المنشأة قبل السماح بذلك.
- كل حالة لها تحميل هيكلي، وفراغ مفيد، وخطأ مفهوم، وإعادة محاولة.
- كل نص عربي قصير وطبيعي، وليس ترجمة حرفية.

## 1. نظام التصميم

### الهوية
- الاحتفاظ بشعار SyndeoCare وألوانها، مع تقليل الألوان المتنافسة.
- لون أساسي واحد للأفعال الرئيسية، وألوان الحالة محجوزة للنجاح والتحذير والخطر والمعلومات.
- خلفية هادئة، سطح أبيض، وحدود خفيفة؛ اللون الدلالي يظهر في شارة أو أيقونة لا كخلفية بطاقة كاملة.
- Cairo للعربية، مع مقياس ثابت للعناوين والنصوص والأرقام.

### قواعد القياس
- شبكة مسافات ثابتة: 4 / 8 / 12 / 16 / 20 / 24 / 32.
- هوامش شاشة موحدة 20، ولمس لا يقل عن 44×44.
- ثلاثة مستويات فقط للزوايا: حقول، بطاقات، لوحات سفلية.
- ظلال محدودة جداً؛ الحدود والفصل والمسافة هي الأساس.
- دعم تكبير خط النظام دون قص النصوص.

### مكتبة المكوّنات
- رؤوس الصفحات: عادي، مع رجوع، ومع بحث/إشعار.
- أزرار: أساسي، ثانوي، نصي، خطر، وأيقونة فقط.
- حقول: نص، بريد، كلمة مرور، بحث، اختيار، تاريخ، وقت، رفع ملف.
- بطاقات موحدة: وظيفة، مناوبة، طلب، دعوة، مقابلة، محادثة، مختص، وثيقة، حالة توثيق.
- عناصر الحالة: شارة، خط زمني، تقدم، تنبيه، رسالة نجاح، snackbar.
- عناصر القوائم: صف إجراء، فاصل، مرشح سريع، segmented control.
- لوحات سفلية موحدة للفلاتر والتأكيدات والإجراءات السياقية.
- Skeleton مطابق لكل بطاقة بدل spinner عام.

## 3. البداية والمصادقة

### فتح التطبيق
- Splash قصيرة بالشعار فقط.
- حارس واحد يحدد: غير مسجل، بلا دور، مختص، منشأة، أو بحاجة لإكمال البداية.
- لا وميض تحميل أو إعادة توجيه مزدوجة.

### تسجيل الدخول
1. البريد الإلكتروني فقط + «متابعة» + Google.
2. إذا كان الحساب موجوداً: كلمة المرور + إظهار/إخفاء + «نسيت كلمة المرور؟».
3. رسائل أخطاء بشرية دون نصوص تقنية.
4. رابط الاستعادة يفتح شاشة تغيير كلمة المرور الصحيحة ثم يعيد المستخدم للتطبيق.

### إنشاء الحساب
1. اختيار مرئي واضح: «مختص صحي» أو «منشأة صحية» مع وصف نتيجة الاختيار.
2. الاسم والبريد والتحقق الفوري.
3. كلمة المرور + التأكيد + مؤشر قوة مفهوم.
4. موافقة صريحة على الشروط والخصوصية بالإصدار الحالي.
5. تحقق البريد بشاشة مستقلة: البريد المرسل إليه، إعادة إرسال، تغيير البريد.

### البداية الموجّهة بعد التسجيل
- المختص: بيانات أساسية ← التخصص والخبرة ← الموقع والتوفر ← السيرة ← الوثائق.
- المنشأة: بيانات المنشأة ← الموقع ونوعها ← جهة الاتصال ← مستندات التوثيق.
- حفظ كل خطوة كمسودة واستكمالها لاحقاً.
- تعرض المنصة ما يمكن للمستخدم فعله الآن وما يتطلب التوثيق، دون خلط بينهما.

## 4. تجربة المختص

### الرئيسية
- تحية قصيرة + صورة الحساب + جرس بعداد.
- بطاقة واحدة بحسب الأولوية:
  - أكمل ملفك، أو
  - وثيقة تحتاج إجراء، أو
  - مقابلة/مناوبة قادمة، أو
  - تحديث مهم على طلب.
- «فرص تناسبك» حتى 3 بطاقات فقط.
- اختصاران: «تصفح الكل» و«نشاطي».
- إزالة الأرقام التي لا تساعد على قرار فوري.

### الاستكشاف
- بحث ثابت أعلى الشاشة.
- تبديل واضح: وظائف / مناوبات.
- فلاتر سريعة: التخصص، المحافظة/المديرية، نوع العمل، الأجر، التاريخ.
- زر فلاتر يفتح لوحة سفلية، ويظهر عدد الفلاتر النشطة.
- حفظ البحث، وترتيب النتائج حسب الأنسب أو الأحدث.
- بطاقة الفرصة تعرض: المسمى، التخصص، الموقع، النوع، الأجر إن كان مسموحاً، وقت النشر، حالة التوثيق الحقيقية، والحفظ.
- لا يظهر اسم المنشأة قبل المرحلة المسموح بها.

### تفاصيل الوظيفة أو المناوبة
- رأس مختصر: المسمى + الحالة + حفظ/مشاركة/إبلاغ.
- صف معلومات بارز: الأجر، الخبرة، الدوام/الوقت، الشواغر.
- وصف، متطلبات، موقع، ومعلومات الخصوصية.
- «لماذا تناسبك؟» يعتمد على بيانات فعلية فقط.
- زر ثابت: تقديم / حجز.
- قبل التنفيذ: ملخص + الموافقة القانونية إن لزم.
- بعد التنفيذ: نجاح واضح + الخطوة التالية + الانتقال إلى نشاطي.

### نشاطي
- أقسام عليا قليلة: الطلبات / المناوبات / الدعوات / المقابلات والتقييمات.
- داخل كل قسم فلاتر حالة لا أكثر من 3 ظاهرة دفعة واحدة.
- بطاقة كل عنصر تعرض حالته والخطوة التالية.
- صفحة التفاصيل تعرض خطاً زمنياً: أُرسل ← روجع ← مقابلة ← قرار.

### ملف المختص
- رأس به الصورة، الاسم، التخصص، وحالة التوثيق الحقيقية.
- بطاقة أهلية واحدة: النسبة، الناقص، والإجراء التالي.
- أقسام: المعلومات، الخبرة، التعليم، السيرة، الوثائق، التوفر، التقييمات.
- كل قسم يعدّل من داخله، مع حفظ ومسودة ورفع ملفات موثوق.

## 5. تجربة المنشأة

### الرئيسية
- عنوان المنشأة وحالة التوثيق.
- بطاقة أولوية واحدة: متقدمون جدد، مناوبة بلا تغطية، مقابلة اليوم، أو مستند ناقص.
- ثلاثة إجراءات أساسية: نشر وظيفة، نشر مناوبة، مراجعة المتقدمين.
- ملخص صغير للفرص النشطة وحالاتها.

### الفرص المنشورة
- وظائف / مناوبات.
- حالات: مسودة، نشطة، مكتملة، مغلقة.
- كل بطاقة: العنوان، عدد المتقدمين/الحجوزات، الشواغر، الحالة، تاريخ الإغلاق.
- قائمة سياقية: تعديل، إغلاق، إعادة فتح، نسخ.
- إنشاء وظيفة أو مناوبة داخل التطبيق بالكامل.

### إنشاء فرصة
- تدفق قصير متدرج:
  1. الأساسيات.
  2. التخصص والموقع والوقت.
  3. الأجر والمتطلبات والشواغر.
  4. معاينة وموافقة قانونية ثم نشر.
- حفظ مسودة تلقائياً، والتحقق بجانب كل حقل.
- المحافظات والمديريات تأتي من القوائم التي يديرها Admin فقط.

### المرشحون والمتقدمون
- تبويبان: متقدمون / مرشحون مقترحون.
- بحث وفلاتر بالتخصص والحالة والتوثيق والتوفر.
- بطاقة مختص مختصرة: التخصص، الخبرة، التقييم المختصر، التوثيق، الموقع المسموح، وحالة الطلب.
- الإجراءات داخل لوحة سفلية: فتح الملف، دعوة، مقابلة، قبول، رفض.
- كل قرار حساس يعرض تأكيداً ونتيجته والخطوة التالية.

### ملف المنشأة
- تعديل البيانات، المواقع، جهات الاتصال، الوثائق، وإعدادات الخصوصية.
- حالة التوثيق وسبب طلب التعديل بلغة واضحة.
- لا وعود أو شارات قبل الموافقة الفعلية.

## 6. الرسائل والإشعارات

### الرسائل
- قائمة محادثات: الصورة، الاسم المسموح، سياق الفرصة، آخر رسالة، الوقت، وعدّاد غير المقروء.
- المحادثة مرتبطة دائماً بوظيفة/مناوبة/طلب ظاهر أعلى الشاشة.
- composer يرتفع فوق لوحة المفاتيح دائماً.
- إرسال متفائل مع حالات: جارٍ الإرسال، تم، فشل/إعادة المحاولة.
- تحميل الرسائل السابقة عند السحب للأعلى.
- تسميات قارئ الشاشة تحدد المرسل والوقت والحالة.

### الإشعارات
- تصنيف: طلبات، دعوات، مقابلات، رسائل، توثيق، نظام.
- «تعليم الكل كمقروء» مع تراجع قصير عند الحاجة.
- كل إشعار يفتح وجهته الدقيقة، لا صفحة عامة.

## 7. الحالات والكلمات داخل الواجهة

### قواعد الكتابة
- عناوين مباشرة: «طلباتك»، «المرشحون»، «وثائق التوثيق».
- الأزرار تصف الفعل: «إرسال الطلب»، «تحديد مقابلة»، «حفظ المسودة».
- لا عبارات عامة مثل «اضغط هنا» أو «حدث خطأ» وحدها.
- الخطأ = ما حدث + ما يمكن فعله: «تعذر تحميل الوظائف. تحقق من الاتصال وحاول مجدداً».
- الفراغ = سبب متوقع + خطوة: «لا توجد طلبات بعد. استكشف الفرص المناسبة لتخصصك».
- النجاح = ما تم + التالي: «تم إرسال طلبك. يمكنك متابعة حالته من نشاطي».

### الحالات المطلوبة لكل صفحة
- فتح أولي، تحميل لاحق، سحب للتحديث، اتصال ضعيف، عدم اتصال، فارغ، خطأ، صلاحية مرفوضة، عنصر محذوف، إجراء جارٍ، نجاح، وفشل قابل لإعادة المحاولة.

## 8. اللمسات الأصلية للجوال
- الكيبورد لا يغطي الحقل أو زر الإجراء على iOS وAndroid.
- الانتقال للحقل التالي من لوحة المفاتيح.
- اهتزاز خفيف للاختيار والنجاح والتحذير فقط.
- سحب للتحديث للقوائم، وسحب المحادثة للأعلى للقديم.
- Bottom sheets للفلاتر والتأكيدات بدل صفحات زائدة.
- احترام safe areas ولوحة المفاتيح وأحجام 320–430.
- تبديل العربية/الإنجليزية يعيد تحميل الواجهة فوراً ويصحح اتجاه الأسهم والتخطيط.

## 9. الوصول والجودة
- تباين WCAG AA على الأقل.
- لا تعتمد أي حالة على اللون وحده؛ نص + أيقونة + لون.
- تسميات عربية وإنجليزية لكل زر أيقوني.
- دعم VoiceOver/TalkBack وترتيب تركيز منطقي.
- دعم تكبير خط النظام والحركة المخففة.
- اختبار كامل عند 320، 360، 390، 430، 768، وعلى iOS وAndroid.

## 10. ترتيب التنفيذ
1. تثبيت tokens والمكوّنات ونظام الاتجاه واللغة.
2. بناء حارس الدخول والمصادقة والبداية الموجّهة.
3. فصل تنقل المختص والمنشأة.
4. إعادة بناء الرئيسية والاستكشاف والتفاصيل للمختص.
5. استكمال الملف والوثائق والنشاط.
6. بناء مساحة المنشأة كاملة: النشر، الفرص، المرشحون، الإجراءات.
7. الرسائل والإشعارات والروابط العميقة.
8. الحالات والاتصال الضعيف والوصول.
9. اختبارات الرحلات كاملة ثم ضبط كل المقاسات.

## نطاق لا يتغير
- لا Stripe أو دفع.
- لا بريد أو WhatsApp مزعوم أنهما يعملان دون الاعتمادات.
- لا تعديل لقواعد الخصوصية أو معنى التوثيق.
- لا لوحة Admin داخل التطبيق؛ الإدارة تبقى على الويب.
- لا نشر تلقائي للموقع أو التطبيق.
