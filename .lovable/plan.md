# مراجعة شاملة للتجربة: كل شاشة لها مكان واحد وحالة واحدة مفهومة

راجعت المنتج فعلياً (الصفحات، التنقل، الشاشات الكبيرة، حالات التحميل) ووجدت مشاكل حقيقية قابلة للإصلاح. هذه خطة الإصلاح.

## ما وجدته فعلاً

1. **إعدادات الحساب موزّعة على ثلاث وجهات**: «الإعدادات» فيها قسم واحد فقط (اللغة) داخل تبويب وحيد بلا معنى، ثم زر يحوّل المستخدم إلى «الإشعارات»، بينما «تفضيلاتي» تحمل التنبيهات والتقرير الشهري. المستخدم لا يعرف أين يغيّر ماذا.
2. **ثماني شاشات ما زالت تكتب «جارٍ التحميل»** بدل الهيكل المؤقت المعتمد في بقية المنتج: التخصصات، الإدارة، ملف المرشح، لوحة المنشأة، الرسائل، الوثائق، توثيق المنشأة، التقرير الشهري.
3. **ثلاث نقاط دخول للتسجيل**: `/auth` و`/register` و`/register/employer`، بمحتوى وأسلوب مختلف لكل منها.
4. **لوحة المنشأة ملف واحد بـ1745 سطراً** والرسائل 1283 سطراً: كل تعديل صغير فيهما يخاطر بكسر شيء آخر.

## ما سأفعله

### 1) توحيد مركز الحساب
صفحة واحدة «الإعدادات» بتبويبات واضحة: **عام** (اللغة والمظهر) · **التنبيهات** (تنبيهات الوظائف) · **الإشعارات** (ما يصلك وأين) · **الأمان** (كلمة المرور، جوجل، الجلسات). تبقى الروابط القديمة تعمل وتحوّل للتبويب الصحيح. يُنقل التقرير الشهري إلى «نشاطي» لأنه بيانات لا إعدادات.

### 2) حالة واحدة لكل انتظار وكل فراغ وكل خطأ
استبدال كل نص «جارٍ التحميل» المتبقي بالهيكل المؤقت نفسه، ومنح كل شاشة فارغة سبباً وإجراءً واحداً، وكل خطأ رسالة بلغة المستخدم مع «إعادة المحاولة».

### 3) مدخل تسجيل واحد
`/register` و`/register/employer` يصبحان واجهة واحدة يختار فيها المستخدم نوع الحساب (كادر / منشأة) بنفس التصميم ونفس النصوص، و`/auth` للدخول فقط مع رابط واضح للتسجيل. الروابط الحالية تبقى تعمل.

### 4) نصوص وأزرار متسقة
مراجعة كل عنوان وزر ورسالة مقابل قاموس المصطلحات الموحّد، وجعل كل زر إجراء يقول ماذا سيحدث بعده، وكل نجاح يعرض الخطوة التالية.

### 5) تفكيك الشاشتين الضخمتين
تقسيم لوحة المنشأة والرسائل إلى أجزاء أصغر حسب التبويبات الحالية — بلا أي تغيير في الشكل أو السلوك — ليصبح الصقل اللاحق آمناً وسريعاً.

### 6) التحقق
رحلتا الكادر والمنشأة كاملتين بحسابين حقيقيين، على 320 و390 و768 و1024 و1440، بالعربية والإنجليزية، مع فحص التباين وأهداف اللمس وعمل لوحة المفاتيح، وعدّ النقرات لكل مهمة أساسية (الهدف ≤3).

## تفاصيل تقنية

- `src/routes/_authenticated/settings.tsx` يستضيف التبويبات ويعيد استخدام `AlertsPanel` والإشعارات ومحتوى `security.tsx`؛ `preferences.tsx` و`notifications.tsx` و`alerts.tsx` تتحول إلى تحويلات مع `search.tab`.
- الهيكل المؤقت عبر `src/components/list-skeleton.tsx` والفراغ عبر `EmptyState` في: `_public.specialties.$slug.tsx`, `admin.tsx`, `facility.candidates.$userId.tsx`, `facility.index.tsx`, `messages.tsx`, `panels/credentials.tsx`, `panels/facility.verification.tsx`, `panels/applicant-report.tsx`.
- التسجيل: مكوّن مشترك واحد يستهلكه `_public.register.index.tsx` و`_public.register.employer.tsx` مع تمرير النية الافتراضية (`sc_signup_intent`) دون تغيير منطق onboarding.
- تفكيك `facility.index.tsx` و`messages.tsx` إلى ملفات تحت `src/components/panels/` بنقل الكود كما هو، مع إبقاء `TXT` والأنواع المشتركة في وحدة واحدة لتفادي الاستيراد الدائري.

## خارج النطاق

لا تغيير في قاعدة البيانات ولا صلاحيات الوصول ولا المعاملات الذرية ولا قواعد العمل المختبرة. تبقى الثوابت: بلا دفع، اليمن والريال اليمني، بلا بيانات وهمية، البريد وواتساب معطّلان حتى تتوفر الاعتمادات، والمتقدمون داخل الفرصة فقط.
