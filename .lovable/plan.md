# إعادة بناء مساحة الإدارة (Admin) في SyndeoCare

## المشكلة
- حساب المدير يرى قائمة المختص (لوحتي، الفرص، نشاطي، الرسائل) ثم «لوحة الإدارة» في الأسفل، لأن القائمة تُبنى حسب «منشأة أو مختص» وتضيف الإدارة كبند زائد.
- لوحة الإدارة صفحة واحدة فيها 15 تبويبًا أفقيًا (وثائق، وثائق منشآت، منشآت، مختصون، وارد، طلبات تعديل، سجل، حذف، بلاغات، متطلبات، مواقع، قانوني، إعدادات، جاهزية...) بلا ترتيب حسب الأولوية ولا صفحة بداية تقول «ماذا ينتظرني الآن».
- تأكيد الدخول بخطوتين يظهر داخل الإطار وقائمة الحساب مكررة في الرأس والقائمة الجانبية.

## الهدف
المدير يدخل فيرى فورًا ما يحتاج قرارًا، ويُنهي كل مراجعة في مكانها دون تنقل زائد، وكل رحلة لها بداية ونهاية واضحة.

## 1. قائمة خاصة بالمدير
- عند وجود دور Admin تكون وجهة الدخول الافتراضية `/admin`، والقائمة الجانبية قائمة إدارة فقط، مقسمة إلى مجموعات:
  - **نظرة عامة**: الرئيسية (ما ينتظر القرار).
  - **المراجعة**: وثائق المختصين، وثائق المنشآت، طلبات تعديل البيانات، البلاغات، طلبات حذف الحساب — لكل بند عدّاد معلّق.
  - **الأشخاص**: المختصون، المنشآت.
  - **التواصل**: صندوق رسائل «تواصل معنا».
  - **إعدادات المنصة**: المحافظات والمديريات، متطلبات الوثائق، المحتوى القانوني، إعدادات المنصة، جاهزية الإطلاق، سجل التغييرات.
- إذا كان للمدير دور آخر (منشأة/مختص) يظهر مبدّل «مساحة العمل» صغير في مركز الحساب بدل خلط القائمتين. «الفرص» و«نشاطي» لا تظهر في مساحة الإدارة.
- على الجوال: شريط سفلي بـ «الرئيسية، المراجعة، الأشخاص، المزيد».

## 2. صفحات مستقلة بدل التبويبات
كل قسم يصبح صفحة لها رابط خاص (`/admin/reviews/credentials`, `/admin/people/facilities`, ...) مع عنوان وسياق وزر رجوع، فيمكن مشاركة الرابط وتحديث الصفحة دون فقدان المكان.

## 3. الرئيسية: «ما ينتظرك»
- بطاقات قليلة بالأعداد المعلقة الحقيقية فقط (وثائق، تعديلات، بلاغات، حذف، رسائل غير مقروءة) — كل بطاقة تفتح الطابور مباشرة.
- قائمة «الأقدم أولًا» لأهم 5 عناصر تنتظر قرارًا، مع زر قرار مباشر.
- حالة فارغة واضحة: «لا شيء ينتظر قرارك الآن».

## 4. رحلة المراجعة الكاملة (مرة واحدة لكل الطوابير)
- قائمة على اليسار/الأعلى + لوحة تفاصيل: فتح الوثيقة ومعاينتها، بيانات صاحبها، ثم «قبول» أو «رفض مع سبب» (أسباب جاهزة + نص).
- بعد القرار ينتقل تلقائيًا للعنصر التالي، مع رسالة تأكيد وإمكانية التراجع خلال ثوانٍ حيث يسمح الخادم.
- فلاتر: معلّق / مقبول / مرفوض، بحث بالاسم، ترتيب الأقدم أولًا.
- من أي عنصر: رابط مباشر لملف المستخدم الكامل (`/admin/users/...`) والعودة لنفس المكان في الطابور.

## 5. الأشخاص
- جدول قابل للبحث والتصفية (حالة التوثيق، المدينة، التخصص) يتحول لبطاقات على الجوال.
- صفحة المستخدم: الملخص، الوثائق وحالتها، النشاط، البلاغات، والإجراءات الإدارية المتاحة فعلًا في الخادم في مكان واحد.

## 6. التواصل والإعدادات
- صندوق الوارد: مقروء/غير مقروء، الرد عبر البريد عند توفره أو نسخ العنوان، أرشفة.
- الإعدادات: نفس الأدوات الحالية بتصميم موحد وحفظ ثابت أسفل الصفحة.

## 7. الدخول بخطوتين
- صفحة التحقق تظهر كصفحة مستقلة نظيفة بلا القائمة الجانبية، وبعد النجاح تعود مباشرة للصفحة المطلوبة.

## 8. الجودة
- عربي RTL وإنجليزي LTR، لمس 44px، تركيز واضح، حالات تحميل وفراغ وخطأ مفهومة، بلا أخطاء خادم خام.
- فحص على 320/390/768/1280/1440 بحساب المدير الحقيقي عبر المتصفح الآلي.

## الحدود
- لا تغيير في الصلاحيات أو قواعد الأمان أو معنى التوثيق؛ كل القرارات تبقى عبر الإجراءات الإدارية الموثوقة الحالية المحمية بالخطوتين.
- لا دفع ولا بيانات وهمية. تطبيق الجوال لا يتغير (الإدارة على الويب).

## تفاصيل تقنية
- `dashboard-shell.tsx`: `ADMIN_NAV` مجمّع، أولوية admin > facility > professional، ومبدّل مساحة عمل محفوظ محليًا (تفضيل عرض فقط، ليس صلاحية).
- تفكيك `admin.tsx` (1146 سطر) إلى `admin.tsx` (layout + بوابة MFA + `<Outlet />`) و`admin.index.tsx` وملفات `admin.reviews.*`, `admin.people.*`, `admin.inbox.tsx`, `admin.settings.*`، مع إعادة استخدام مكونات `admin-*.tsx` الحالية.
- مكون `ReviewQueue` مشترك (list/detail، next-after-decide، فلاتر في search params).
- عدّادات عبر TanStack Query من الاستعلامات الموجودة؛ إعادة توجيه من `/admin?tab=x` القديم.
- `mfa-challenge` خارج `DashboardShell`.
